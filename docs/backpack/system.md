# 系统设置

本页讲 XTac-UMI Collector 控制台(下称控制台)「系统」页里的每个子项:它是什么、什么时候需要改、怎么改、改错了会怎样。读完能独立完成首次部署时的夹爪标定、采集设置、上传凭据与网络配置,并知道哪些项日常不该碰。

## 系统页有什么

控制台顶栏进「系统」,左侧子项按使用频率排列;每个子项都能用 `/system/<id>` 直链打开,方便支持人员发链接。

| 子项 | 直链 | 用途 | 什么时候来 |
|---|---|---|---|
| [设备信息](#device-info) | `/system/device-info` | 版本、序列号、头显详情、夹爪 MCU 与摄像头清单 | 报修、对机器、升级后核对 |
| [夹爪配置](#gripper) | `/system/gripper-calibration` | 夹爪开合标定、MCU 固件升级 | 首次部署、换过夹爪 |
| [采集设置](#capture-settings) | `/system/capture-settings` | 采集模式、腕部去畸变、录制快捷键、语音播报、灯语与按键说明 | 首次部署、接线变了、想调现场反馈 |
| [上传配置](#upload) | `/system/upload` | 远端上传凭据(ModelScope / S3 / FTP / NFS / STS) | 要上传数据之前 |
| [网络 / 配网](#wifi) | `/system/wifi` | 连现场 WiFi、有线 IP、热点入口 | 换场地、要多人访问 |
| [相机参数包](#camera-profiles) | `/system/camera-profiles` | 导入或恢复相机参数包(.xpack) | 技术支持给了新包 |
| [系统更新](#update) | `/system/update` | 升级与回滚 | 有新版本时 |
| [纳管](#matrix) | `/system/matrix` | 多机管理接入 | 当前不需要 |

!!! warning "先停录制"
    录制进行中,切换采集模式、改腕部去畸变配置、夹爪开合标定、夹爪固件升级、相机参数包上传 / 恢复、系统更新应用都会被设备拒绝(界面提示「录制进行中」)。遇到这类提示先在监控页停止录制。

## 设备信息 {#device-info}

![设备信息页](../assets/backpack/device-info.webp)

一页看全这台背包的软件版本、身份序列号、头显详情、夹爪 MCU 与摄像头清单。全部只读,不需要改。

- 指标卡:采集端版本、git、构建时间、架构、设备 SN(产线烧录、印在机身标签上的那串)、硬件序列、节点 ID、模式(standalone / matrix)。读不到的显示 `--`。
- 头显:每台一张卡,显示在线 / 离线,以及 Head SN、XUMI 软件版本、分辨率,和左右目相机内参(原始 4 项顺序)、外参(原始 4×4 顺序)。已发现头显但还没收到相机参数时提示「已发现头显,尚未收到相机参数。」,没连头显时显示「未检测到头显。」。
- 夹爪 MCU:每爪一行,左爪 / 右爪徽章、SN、固件版本、波特率、标定掩码(0x 十六进制)、串口端口。
- 摄像头:运行时聚合的逻辑相机清单,每行显示侧别·角色、product / serial 与 v4l2 节点,离线的标注「(离线)」。

四份数据独立拉取,头显或 MCU 掉线不会把整页清空;右上角「刷新」手动重拉。

!!! warning "头显认 Head SN,不认连接 ID"
    0.3.16 起头显的身份以「Head SN」与「XUMI 软件版本」为准,两者取头显随相机参数上报的值。旧版本页面上那个「连接 ID」已经不再显示,也不再能当作头显的设备 SN —— 记录、报修、对机器都改用 Head SN。

什么时候来这一页:

- 报修、对机器:抄设备 SN 与硬件序列,头显抄 Head SN。认机只认这几样,不要记 IP,DHCP 地址会变。
- 升级后:核对「采集端版本 / git / 构建时间」,确认新版真的生效。文档按 0.3.16 编写,实际以这里显示为准。
- 监控页相机路数与预期对不上:先看这里哪台相机「(离线)」。
- 夹爪标定前:看固件版本是否 ≥ 1.2.0.0(即 PC 版所说的命令集 V2.1、构建号 1.2.0,见[三套编号](../pc/versions.md#v21)),低于它的爪不支持行程标定。

## 夹爪配置 {#gripper}

![夹爪配置页](../assets/backpack/gripper.webp)

做夹爪开合(行程)标定:先闭合写零点,再全开写最大行程,两个值都写进夹爪 MCU 的 flash;同一页还能给夹爪 MCU 刷固件。

页面上半是左右两张 URDF 俯视预览,实时显示编码器角度(rad 与度)、旋转进度与已存最大行程(未标定显示「未标定」);下面每爪一张标定卡:状态(读取中 / 离线 / 不支持 / 已标定 / 未标定)、固件 SN、固件版本、角色(Leader / Follower)、当前角度、已存最大行程、当前归一化开度。只有支持标定的爪会出现两步向导。

### 什么时候需要标

标定值存在夹爪自己的 flash 里,断电不丢、换背包不用重标,一只爪标一次就够。控制台向导与 PC 版的 `calibrate.py` 脚本写的是同一份值,两者等价:在任一处标过,另一处不用再标。什么情况算"没标"或"标歪了"(拆装过编码器、动过机械限位、擦除过固件)、以及双爪只标一侧为什么比都不标更糟,见 PC 版[夹爪标定](../pc/calibration.md#41),规则完全一样。在背包版里的表现是:标定卡显示「未标定」,或监控页里夹爪张到机械极限时归一化开度顶不到 1.0。

### 怎么标

逐爪做,顺序不可跳;第 1 步没完成时第 2 步按钮锁定。

1. 确认该爪在线,状态不是「离线 / 不支持」。行程标定需要 Leader 固件 ≥ 1.2.0.0(即 PC 版所说的命令集 V2.1、构建号 1.2.0,见[三套编号](../pc/versions.md#v21)),Follower 夹爪不支持;显示「不支持」时先看固件版本或确认接的是主夹爪。
2. 把夹爪完全闭合并握住,点「确认已完全闭合」,确认弹窗后写入零点。设备会自动回读,残差 ≤ 0.01 rad 为正常;超差会提示重做第 1 步。
3. 把夹爪打开到机械极限并保持不动,点「确认已完全打开」,写入最大行程。读数必须大于 0,写入后立即回读校验。
4. 看到「开合标定完成:最大行程 … rad,归一化开度范围为 0–1」即完成,另一侧重复。

全开角没有固定标准值,机械极限处的实测值就是标定值。

!!! danger "写 flash 直接覆盖旧值,而且要一次做完"
    零点与最大行程写入即覆盖 MCU flash,不可撤销。第 2 步必须紧接第 1 步完成:只写零点不写行程是半标定状态,归一化开度不可用;双爪只标一侧会让左右开合度落在不同刻度上,数据里看不出异常。要标就两侧都标完。

### 夹爪固件升级

同页下方的「夹爪固件升级」面板:选目标爪、选 `.bin`、「上传并刷写」,刷完等夹爪重启后给背包断电再上电。步骤、按角色选镜像的规则与刷后为什么必须断电见[夹爪固件](update.md#gripper-firmware)。

## 采集设置 {#capture-settings}

这一页管的是**现场怎么触发、设备怎么反馈**:录制快捷键、语音播报、灯语与设备按键。页首另有一块「当前项目采集配置」,只读展示这个项目录哪几路、导出成什么样。

**录哪几路、导出成什么样不在这一页改** —— 那些是项目的属性,在[新建项目](monitor-record.md#project-task)时定下,建完就冻结。这一页只让你核对当前项目用的是哪一套。

### 当前项目采集配置 {#capture-mode}

![采集模式](../assets/backpack/capture-mode.webp)

页首这一块只读展示当前项目的四项采集与导出参数。它们在建项目时选定、之后不可更改,所以这里没有任何可点的开关 —— 要换一套参数,新建一个项目。

**项目采集模式**决定录几只爪、要不要头显,以及监控页布局、录制内容与导出的通道契约。六种预设:

| 模式 | 夹爪 | 头显 | 相机路数 |
|---|---|---|---|
| 双爪 | 2 只夹爪 | 不含头显 | 6 路 |
| 双爪 + 头显双目 | 2 只夹爪 | PICO 双目 | 8 路 |
| 双爪 + 头显右单目 | 2 只夹爪 | PICO 右眼 | 7 路 |
| 单爪 | 1 只夹爪 | 不含头显 | 3 路 |
| 单爪 + 头显双目 | 1 只夹爪 | PICO 双目 | 5 路 |
| 仅头显双目 | 无夹爪 | PICO 双目 | 2 路 |

「单爪」的左右侧不用选,由设备按夹爪实际接在哪一侧自动判定,换爪不用改配置。

另外三项:**项目 PICO 分辨率**(每眼 `640x480` 或 `1024x768`,只有带头显的模式要选)、**项目触觉导出方向**(`700 × 400 · 当前方向`,或 `400 × 700 · 再逆时针 90° · SDK 方向`)、**PICO 图像源**(鱼眼原图或去畸变画面)与**腕部鱼眼矫正**开关。建项目之前先想清楚这几项,建完改不了。

!!! warning "采集配置建项目时就冻结了,选错只能重建项目"
    这四项在项目创建后不可更改,录制期间设备也不会替你改。模式选少了,之后这个项目的录制就少通道,导出预检会按剖面拦截(例如「仅头显」的数据过不了双臂剖面的 LeRobot 预检)。历史项目没指定过的字段保持原样,可以继续查看、导出和上传;要用新参数就新建一个项目。

### 腕部鱼眼矫正与触觉方向 {#undistort}

这两项同属项目采集配置,在建项目时随模式一起定下,这一页只读展示。

**腕部鱼眼矫正**:腕部相机是广角镜头,画面四周有明显拉伸;开启后**导出的数据集里**腕部画面会被矫正成接近直线的透视。它是一个**导出项**,不是录制项 —— 录制文件里保存的始终是相机原始鱼眼图,矫正只在导出时进行;历史 episode 重新导出,得到的仍是录制当时冻结的取景。

矫正参数读自夹爪 MCU 的 flash(产测标定时写入),每爪一行显示状态:「已标定 · 基准 W×H」「未标定 · 按默认内参矫正」「未标定」或「MCU 离线」。

!!! warning "「未标定 · 按默认内参矫正」不等于标好了"
    未标定的那一侧也会用该型号镜头的通用参数矫正,导出的腕部画面同样接近直线透视。但通用参数不含单台镜头的个体差异,精度不及逐台标定,所以这一侧的状态仍然显示「未标定」,提示这台设备值得补做一次标定。补做完成后自动改用本台设备自己的参数,现场不需要任何操作。未标定不会拦住采集。

### 录制快捷键 {#keybinding}

浏览器里「开始 / 结束录制」的键盘快捷键,现场不用回到界面点按钮。什么时候用:平板或电脑接了键盘。

怎么改:点「绑定快捷键」,按下想用的键(可带 Ctrl / Alt / Shift)即完成;「重新绑定」换键,「清除」撤销,绑定中按 Esc(界面上是「取消(Esc)」)取消。快捷键存在当前浏览器里,换一台平板要重新绑;只在控制台页面打开时生效,输入框聚焦时不触发,不会在打任务指令时误开录。绑错了没有后果,清除重绑即可。

快捷键与下面的设备按键是两条独立的路:快捷键要浏览器在线并聚焦,设备按键不经过浏览器,是现场推荐的录制方式。

### 语音播报 {#voice}

设备喇叭在关键节点用中文语音提示,不需要平板在旁边,也不受浏览器影响。理由很实际:采集时双手都在夹爪上、眼睛盯着现场,看灯要专门抬头,语音不用。

出声的时机有四种,对应五句固定播报:

| 时机 | 播报 |
|---|---|
| 开始录制 | 「录制开始」 |
| 一条录完 | 「录制完成请重置环境」 |
| 录制中出现严重问题 | 「录制失败」 |
| 录制中夹爪或头显掉线 | 「夹爪连接失败」/「pico连接失败」 |

这一块里可调的只有两样,都是重启后保留的:

- 开关:一键静音(界面显示「开启」/「已静音」)。
- 播放音量:0–100 的滑块(0.3.16 新增),只调播放阶段的软件增益,不改 WAV 素材也不动系统声卡;最大档相当于 +3 dB。

每句话旁边都有一个「试听「…」」按钮,走的是与真实播报完全相同的链路,所以试听没声也能分辨原因:当前静音会提示先打开开关,设备没有可用音频输出会提示语音播报本次运行已停用。

播报的内容与时机是固定值,现场改不了,改口径要发版 —— 同一批设备的行为因此完全一致。

### 指示灯与设备按键

同页最下面是灯语与设备按键的对照表,只读,不可配置:按键一栏列出右爪长按 / 左爪长按 / 左爪双击 / 删除确认中按右爪的操作顺序;灯语一栏里每种灯按真实的形状与节奏演示 —— 常亮、呼吸、闪、脉冲、快闪各是什么样一眼可辨,不必再从文字里分辨「快闪」和「脉冲」的差别,删除确认时的紫灯也在表里。

绑定爪位、键位、时序与灯语口径是全机队固定值,现场不可调,控制台里也没有改的入口;当前生效值就在这一块查看。手势与灯语的正文见[夹爪按键、指示灯与序列号](../common/gripper.md#buttons)。

## 上传配置 {#upload}

![上传配置页](../assets/backpack/upload.webp)

上传配置是把数据传到远端用的账号凭据。可以配多档,每档一个名字(命名槽位),新建项目时绑定其中一档,该项目之后的上传默认走它。一台背包给不同客户或项目采数据、各自传到不同去处,就各建一档。凭据只在这里填一次,导出窗口里不再填仓库和令牌。

后端种类有五种,字段按种类切换(它们的凭据没有一个字段是共用的):

| 种类 | 传什么 | 要填 |
|---|---|---|
| ModelScope | LeRobot 数据集 | Owner(账号 / 组织)、Token、新建仓库可见性 |
| S3 对象存储 | LeRobot 数据集 | 桶名、Endpoint、Region(可留空)、Access Key、Secret Key |
| FTP / FTPS | LeRobot 数据集与导出 MCAP | FTP 服务器、端口、用户名、密码、目标目录、连接安全;选 FTPS 时可另填私有 CA |
| NFS 网络存储 | LeRobot 数据集与导出 MCAP | 服务器、导出路径、协议版本;目标子目录、UID / GID、端口按需要填 |
| STS(导出 MCAP) | 离线导出的 `*.train.mcap` | Server、Account / OpenID、Project、Project Type、Task ID(可留空) |

是否支持 FTP / FTPS 与 NFS 这两档,以设备的 系统 → 上传配置 页面里有没有出现对应选项为准;没有这些选项时联系技术支持确认设备版本。

列表里每档显示名称、种类徽章与目标(owner / 桶 / project),以及凭据尾四位掩码和「校验 / 编辑 / 删除」。

五档的目录命名是统一的:**`<根>/ 项目名称 / 模式前缀-任务名-日期 /`** —— 「根」按种类分别是 Owner、桶或目标根目录。项目目录用的是**建项目时填的名称**,任务名不用自己带模式前缀和日期,设备会加。已经上传过的任务继续用它原来的目录,不会因为这条规则改名。

各种类要知道的:

- **ModelScope**:数据集仓库建在 Owner 名下(`<owner>/<仓库名>`)。可见性选私有(推荐)或公开,只在首次建仓时生效,改这里不会动已存在的仓库。获取 token:登录 [ModelScope](https://www.modelscope.cn/my/overview),点头像 → 账号设置 → 访问令牌 → 新建访问令牌。
- **S3**:桶要预先建好,设备只往里写、不会建桶,也管不了桶的访问策略(所以没有可见性选项)。
- **FTP / FTPS**:推荐用 FTPS(显式 TLS);选明文 FTP 时账号、密码与数据都不加密。目标目录必须**已经存在**,并且从 `/` 开始写,路径以 FTP 登录后看到的根目录为准。NAS 用私有证书时,把签发该证书的 CA 填进「私有 CA 证书」,并且服务器地址必须与证书匹配。更换服务器、端口、账号或把连接安全从 FTPS 改成明文之后,密码需要重新填写。
- **NFS**:协议版本默认「自动」(优先 v4.1,其次 v3),也可以固定为 v3 或 v4.1;v4.0 只是实验支持,不支持 v4.2 与 Kerberos。目标子目录必须**已经存在**,设备不会替你创建;UID / GID 留空时用设备账户的身份写入。
- **STS**:只上传离线导出的训练 MCAP,不接收 LeRobot。每个文件上传前由 Server 签发短期凭据,设备 SN 固定用本机背包的,不能在配置里覆盖。

怎么配:

1. 「新建配置」,填名称、选后端种类、填该种类的字段,保存。
2. 点按钮自查这一档:ModelScope、S3 与 STS 上是「校验」,NFS 与 FTP / FTPS 上是「检测读写」。
    - 「校验」:ModelScope 拿 token 验证并核对线上账号与填写的 owner 是否一致;S3 校验桶可读写;STS 只校验配置完整,账号鉴权在每个 MCAP 上传时才做。
    - 「检测读写」:在目标位置真的把创建、写入、读回、重命名与删除跑一遍,验证权限齐不齐。通过后这一档显示可用状态(NFS 还会报出导出的可用空间);没通过时先按页面上的提示查目录、权限、协议版本或证书。
    - 保存配置**不要求**检测先通过,检测没过也**不会**自动拦住上传 —— 它只告诉你这个目标现在能不能写。改过配置之后上次的检测结果作废,要重新检测一次。
3. 新建项目时在「上传后端」里选这档;已有项目在项目行的「上传后端」里补绑。项目没绑定时,导出窗口里可以临时从下拉选一档。

上传本身的步骤见[导出与上传](projects-export.md#export)。

!!! warning "绑错档撤不回来"
    把 A 客户的数据传进 B 客户的账号后,ModelScope 的程序化删除受限,撤回要走它的网页控制台;公开发布同样不可逆。建项目时核对绑定的是哪一档。项目上传过一次之后,仓库坐标就记在游标里,改绑到会换仓库的配置会被设备拒绝。

!!! warning "配过 NFS 或 FTP / FTPS 之后不要直接回退到旧版本"
    不支持这两档的旧版本可能读不出整份上传配置,连原有的 ModelScope、S3、STS 几档也会一起失效。确需回退时,先把新建的这两档删掉,或联系技术支持处理配置备份。

其他要知道的:凭据保存在设备状态盘(权限 0600),保存后不再回显,编辑时留空表示保留设备上已存的那份;编辑时换了后端种类,凭据必须重填,没有可以沿用的字段。删除一档不影响已上传的数据,绑定了它的项目在上传时会提示重新绑定。

## 网络 / 配网 {#wifi}

![网络 / 配网页](../assets/backpack/wifi.webp)

这一页管背包的三个网络口:自己常驻的配网热点(只读展示)、作为客户端连现场 WiFi、有线 IPv4。三种打开控制台的方式与各自的适用场景在[网络与控制台入口](network.md),这里只讲怎么改。

页面分四块:

- 本机配网热点(SoftAP · 5G,常驻):热点 SSID、WPA2 密码、浏览器入口 `http://xense-<序列号后 6 位>.local` 与备用入口 `http://192.168.44.1`。这一块不可改,是永远的兜底入口。
- 当前外网连接(wlan0):所连 SSID、IPv4,「断开并遗忘」。
- 附近 WiFi:「重新扫描」,列表显示 SSID、信号强度、`5G` 与「开放」/「当前」徽章。
- 有线连接:网卡、当前地址、网关、DNS 只读展示;模式「自动(DHCP)」或「静态 IP」,「应用有线配置」。

### 连现场 WiFi {#wifi-site}

什么时候需要:现场有可用的 5 GHz WiFi,想让同网段的多台电脑或平板直接访问背包。只有一台平板、走热点就够的场景不需要配。

推荐全程通过热点操作,不需要背包先有网:

1. 手机或平板连背包热点 `xense-<序列号后 6 位>`(密码见机身标签或本页)。
2. 浏览器打开 `http://192.168.44.1`(见[热点入口](network.md#softap)),进 系统 → 网络 / 配网。
3. 「重新扫描」,点目标 SSID,输密码,连接;开放网点一下直接连。
4. 配完手机断开热点即可。背包会记住这个网络,重启后自动重连;「断开并遗忘」会删掉这条记录。

只列 5 GHz:热点与现场 WiFi 共用同一路射频,现场 WiFi 一旦落到 2.4 GHz,热点会被拽到同一信道而掉线。所以扫描列表在设备端就滤掉了 2.4 GHz,2.4 GHz-only 的网络看不到也连不上;双频同名的 SSID 会被钉在 5 GHz 上。现场只有 2.4 GHz 时改用有线或直接走热点。

### 有线 IP {#wifi-wired}

有线口出厂默认 DHCP,插上路由器 LAN 口即可用,日常不用动。只有现场没有 DHCP(背包与电脑网线直连、接无 DHCP 的交换机)或 IT 要求固定地址时才配静态:模式选「静态 IP」,IP 带 CIDR 前缀(如 `192.168.1.10/24`,多个用逗号分隔),网关与 DNS 可留空(纯直连就该留空),「应用有线配置」。没插网线时也能保存,插线后生效。静态模式下 IP 为空无法提交。有线接入的拓扑见[固定工位的布置](unbox-connect.md#desk)。

!!! warning "改有线 IP 可能把自己踢下线"
    应用后背包的有线 IP 会变。你正通过有线访问控制台的话,页面会断开,要用新地址重新打开;换址过程中页面可能报网络错误,但配置多半已经生效。改砸了连热点走 `192.168.44.1`,把模式改回「自动(DHCP)」即可恢复。

## 相机参数包 {#camera-profiles}

![相机参数包页](../assets/backpack/camera-profiles.webp)

相机参数包(`.xpack`)装的是相机的标定与曝光参数。背包出厂时已内置一套,日常不需要动这一页;只有技术支持给了新的 `.xpack`(更换或返修相机模组之后、参数更新时)才需要导入。

页面显示当前参数包状态(出厂默认 / 已自定义),逐包列出前缀、大小与「已替换 / 默认」标签;下面是「更换参数包」:选 `.xpack` 文件「上传并生效」(带进度条),或「恢复默认」退回出厂(已是默认时按钮禁用)。

怎么导入:

1. 选 `.xpack`,点「上传并生效」,确认弹窗。
2. 等提示「已生效;在线相机已重开验证,离线相机会在上线时应用」。
3. 要退回出厂:「恢复默认」,确认。

上传即生效,没有「暂存后再应用」的中间态,相机会重新打开并验证参数,所以录制期间会被拒绝(提示「操作被拒绝:正在录制或相机状态发生变化,请停止录制并刷新后重试」)。上传内容与当前一致时不做改动;激活失败时新包会被自动清掉,设备停在原来的参数上,不留残包。导入了不匹配的包但激活成功,表现是画面异常,「恢复默认」即可退回。
